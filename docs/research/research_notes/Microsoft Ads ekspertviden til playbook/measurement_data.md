## 1. UET tag, conversion goals, counting, windows, view-through, revenue, enhanced/offline conversions, Clarity, CAPI

### Takeaway
Conversions in Microsoft Advertising are UET- (or offline/CAPI-) based events that are only counted when Microsoft can tie them to a prior ad click (or, for Audience/MSAN ads, an impression), they are **reported on the click date**, and only goals with "Include in Conversions" on feed the `Conversions`/`Revenue`/CPA/ROAS columns and automated bidding; everything is in `All conversions`. Window default 30 days (1 min to 90 days), counting default "All", view-through window default 1 day.

### Cited Findings
**Goal types** [Official]
- Goal types: Destination URL (Equals/Begins with/Contains/Regex; http(s) and www ignored), Event (custom event action/category/label/value; requires customising the UET tag), Duration (1 s to 23:59:59), Pages viewed per visit (0 to 9,999,999), Product (purchase via ad click; "not everyone has this feature yet"), Mobile app install (Windows Store, Google Play, Apple App Store), Offline conversions, Store visits and In-store transactions (both limited rollout). — [What are conversion goals and goal types? (ms.date 2026-06-18)](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2ctgoaltype)
- Destination URL and custom event goals are matched case-insensitively. Creating a goal automatically enables MSCLKID auto-tagging (`?msclkid=...` appended to the final URL; UET stores it in a first-party cookie). A "Create conversion goal" recommendation, when applied, is by default included in "Conversions" and affects automated bidding. — [How do I create a conversion goal? (ms.date 2026-05-30)](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_proc_uetv2creategoal)
- "Simplified conversion goal setup" (auto-detects button clicks, purchases, checkouts, subscriptions) does **not** support variable revenue, app or offline goals; automated bid strategies require "Optimize campaign performance" (= Include in Conversions) to be enabled on the goal. — [How do I create a conversion goal?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_proc_uetv2creategoal)
- Microsoft lists UET setup guides for Shopify, WordPress.com, Wix, Squarespace and BigCommerce and tag managers (GTM, Tealium, Adobe, Ensighten, Qubit, Signal); **Magento/Adobe Commerce is not among the listed platforms**. — [msa-help table of contents](https://learn.microsoft.com/en-us/advertising/msa-help/toc.json) (retrieved 2026-11-20)

**Primary vs. secondary ("Include in Conversions")** [Official]
- Goals with Include in "Conversions" unchecked are shown only in "All conversions" columns (All conv., All conv. rate, All conv. revenue) and **no longer factor into automated bidding**. View-through conversions are not affected by this setting and "appear in both columns by default". — [Conversions versus All conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_convsvsallconvs)
- API: `ExcludeFromBidding = true` removes the goal from the `Conversions`, `ConversionRate`, `CostPerConversion`, `ReturnOnAdSpend`, `RevenuePerConversion` **and `Revenue`** report columns; it equals unchecking Include in Conversions. `AllConversions`/`AllConversionRate` include all goals. — [ConversionGoal data object](https://learn.microsoft.com/en-us/advertising/campaign-management-service/conversiongoal?view=bingads-13); [SearchQueryPerformanceReportColumn](https://learn.microsoft.com/en-us/advertising/reporting-service/searchqueryperformancereportcolumn?view=bingads-13)
- Campaign-level conversion goals override the account-level setting: the campaign's `Conversions` column then contains only the selected goals; changes **apply only going forward** (no restatement of past Conv.). Not supported for sponsored product ads / cashback CPS. — [What are campaign level conversions?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_campaignlevelconv)
- Custom columns now support all conversion metrics, segmentable by goal name (All Conv., CPA, ROAS) — announced 2026-05-19. — [Microsoft blog, May 2026 product news](https://about.ads.microsoft.com/en/blog/post/may-2026/new-import-center-and-other-product-news-for-may-2026)

**Counting, window, revenue** [Official]
- Counting: "All" (default; every conversion after a click; typical for sales) vs. "Unique" (one per click; typical for leads). Example: unique leads + all sales; 1 click → 2 leads + 2 sales = 3 conversions. — [Change how you count conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2count); [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks)
- Conversion window: 1 minute to 90 days, **default 30 days**; API `ConversionWindowInMinutes` default 43,200, max 129,600. Changing counting or window **only applies going forward**. — [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks); [ConversionGoal](https://learn.microsoft.com/en-us/advertising/campaign-management-service/conversiongoal?view=bingads-13)
- Revenue: fixed, variable (default value used when none is sent; only for destination URL and event goals) or none; 0 to 9,999,999 with 3 decimals; non-account currency converted with the average daily FX rate; goals scoped to "all accounts" can't set a currency. — [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks)
- Microsoft "does not currently include any functionality to detect or eliminate test, fraudulent or duplicate conversions"; Unique counting is not de-duplication of fraud. Duplicate UET tags on the confirmation page or several goals matching the same event inflate counts. — [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks); [Discrepancy article](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_baawdiscrepancy)
- Restate/retract: online conversions need `transaction_id` (pilot), offline need MSCLKID; max 100,000 rows per upload. — [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks)

**View-through** [Official]
- View-through conversions apply to Audience ads and Search ads extended to the Audience Network; anyone who clicked any of your ads is excluded; "attributed to the last impression and reported at the time of the impression". Default view-through window **1 day**; included in "All conv." by default (account-level option), but never in "All conv. CPA". — [What are view-through conversions?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_viewthroughconv)
- API max view-through window 43,200 minutes (30 days); account property `IncludeViewThroughConversions`. — [ConversionGoal](https://learn.microsoft.com/en-us/advertising/campaign-management-service/conversiongoal?view=bingads-13); [AccountPropertyName](https://learn.microsoft.com/en-us/advertising/campaign-management-service/accountpropertyname?view=bingads-13)

**Enhanced conversions** [Official]
- Enabled **per conversion goal** ("Turn on Enhanced conversions"); sends hashed email and/or phone from the conversion page. Email: formatting/hashing optional (Microsoft hashes if not hashed); phone: you must format, hashing optional. Also usable for offline imports (hashed columns). — [Enhanced conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_enhancedconversions)
- Moved out of beta to all markets in February 2024; opt-in per goal. I found no source for a 2025–2026 change to on-by-default. — [Microsoft blog Feb 2024 (search-result text)](https://about.ads.microsoft.com/en/blog/post/february-2024/enhanced-conversions-and-other-updates-for-february); [Search Engine Roundtable](https://seroundtable.com/microsoft-advertising-enhanced-conversions-expansion-more-36848.html) [Third-party]

**Offline conversion import** [Official]
- Requires MSCLKID (captured from the landing URL into a cookie/hidden form field, stored in the CRM) or hashed email/phone; upload must be within **90 days of the last click**; wait **2 hours** after creating the goal and about 1 hour after the click; data can take **up to 6 hours** to show. Time zone can be given per row or once in the "Parameters" row (not necessarily UTC). Too-old or foreign click IDs still show as "uploaded successfully" because the format is valid. — [Tracking offline conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2offlineconversion)
- For Maximize conversions/Target CPA: upload offline conversions daily, ideally within two days of the conversion; if most conversions happen >7 days after the click, Microsoft recommends not using Max conversions/Target CPA. — [Bid strategies](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy)
- API `OfflineConversion` has `HashedEmailAddress`, `HashedPhoneNumber`, `ExternalAttributionModel` and `ExternalAttributionCredit` fields. — [OfflineConversion data object](https://learn.microsoft.com/en-us/advertising/campaign-management-service/offlineconversion?view=bingads-13)

**Clarity and CAPI** [Official]
- UET can be linked to Microsoft Clarity (heatmaps, recordings) via "Enable Microsoft Clarity" on the tag; new tags don't capture Clarity data by default; Clarity consent must be set separately. — [UET and Clarity integration](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_clarity); [Setting up UET for consent mode](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_consent)
- "Code-free, powered by Microsoft Clarity" conversion goals (event or variable-revenue tiles picked on the live site) — limited rollout. — [Code-free conversion goals](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_clarity_codefree)
- Conversions API (CAPI): server-side UET events plus a client-side ID-sync pixel; should send visitor IDs, the latest MSCLKID, hashed email/phone and consent status; limited rollout ("not everyone has this feature yet"). GA vs. beta status is reported inconsistently in the trade press. — [Conversions API (CAPI)](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_aboutcapi); search summary of ppc.land vs. Search Engine Land [Search-result text]

**Google import side effect** [Third-party, quoting a Microsoft email]
- Since about June 2024, every Google Ads import, scheduled or not, also **imports Google conversion goals by default** (setting "Import conversion goal" in the import settings). Value-based strategies then optimise on those imported goals. Practitioners warned this can "mess stuff up". — [Search Engine Roundtable, 2024-06-06](https://www.seroundtable.com/microsoft-advertising-import-google-ads-conversion-data-37520.html)

### Inferences
- For a Danish Magento shop the realistic UET routes are GTM (official UET template) or hand-coded tags. The purchase goal should be an Event or Destination URL goal with **variable revenue** (simplified setup can't do variable revenue).
- If `Conversions` and `All conversions` differ a lot, a secondary goal (add-to-cart, page views) or view-through conversions are present. ROAS/CPA columns follow primary goals only.
- An account that has run Google imports since mid-2024 may hold several imported goals next to its own UET purchase goal. Check for double counting (two primary goals firing on the same order) before trusting conversion counts.

### Gaps
- Exact default of "Unique vs. All" for imported Google goals and for simplified-setup goals: not documented in the pages read.
- Enhanced conversions: no Microsoft statement on match-rate uplift or Danish availability found.

## 2. Consent in the EEA (UET Consent Mode, TCF, enforcement, effect on data, modeled conversions)

### Takeaway
Since **5 May 2025** Microsoft requires a consent signal (UET Consent Mode `ad_storage`, or IAB TCF 2.0, never both) for EEA/UK/CH traffic. Without any signal Microsoft **stops tracking UET conversions and filling remarketing lists**. With a signal, conversions from users who deny are lost unless **modeled conversions** (GA in EEA/UK/CH, needs ≥700 weekly clicks in the market) fill part of the gap. Modeled conversions are fractional and sit inside the `Conversions` column.

### Cited Findings
- Microsoft announced on 31 March 2025 that consent signals must be provided by **5 May 2025** for site visits from the EEA, UK and Switzerland; three routes (UET Consent Mode, TCF 2.0 string/CMP, or via tag managers such as GTM); "only one of them should be implemented". Failing to do so "will impact your advertising performance". — [Microsoft blog, 2025-03-31](https://about.ads.microsoft.com/en/blog/post/march-2025/providing-user-consent-signals-on-your-microsoft-campaigns-by-may-5-2025) [Official]
- Consequence without Consent Mode/TCF: "we will stop tracking your UET-based conversions and populating your remarketing lists"; with it, tracking continues "although you may observe a drop in these volumes depending on user cookie consent choices". Never use Consent Mode and TCF simultaneously. Only `ad_storage` is enforced; `ad_user_data`/`ad_personalization` optional. — [FAQ – UET and user consent](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_consentfaq) [Official]
- `ad_storage=granted`: first- and third-party UET cookies read/written; **"If no default is set, UET uses granted by default."** `denied`: first-party cookies not read or written; third-party cookies read only for fraud/spam. — [Setting up UET for consent mode](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_consent) [Official]
- UET must load before the banner interaction with default **denied**, updated to granted on consent; script placed as high as possible in `<head>`. Microsoft flags non-compliance when MUID, _uetvid, _uetsid, _uetsid_exp, _uetvid_exp or MSPTC cookies are set before banner interaction or after "Refuse". Then Microsoft device identifiers are neither set nor read → conversion tracking and remarketing hit. — [FAQ – UET and user consent](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_consentfaq) [Official]
- TCF: add Microsoft (vendor ID 1126) and Xandr (vendor ID 32); purposes 1, 2, 3, 4, 7, 9, 10. — [FAQ – UET and user consent](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_consentfaq) [Official]
- Basic vs. Advanced Consent Mode: Basic blocks the tag until consent (generic modeling); Advanced loads immediately with denied default and collects anonymised data for "more precise modeling tailored to the advertiser". Microsoft recommends **Advanced**. Supported CMPs include Cookiebot, **Cookie Information** (Danish), CookieYes, Didomi, OneTrust, Usercentrics, Iubenda and others; plus the GTM template. — [Setting up UET for consent mode](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_consent) [Official]
- Modeled conversions: GA in EEA, Switzerland and Great Britain (pilot in US); fractional; **included in the Conversions column** (and Revenue); uplift = modeled / observed per domain-country pair, refreshed daily over a 60-day period. Eligibility: UET (not offline), correct Consent Mode/TCF, **minimum 700 ad clicks per week in the targeted market**, plus a confidence threshold; a UI notification appears when activated. Microsoft advises gradually readjusting tCPA/tROAS targets that were loosened to compensate for consent losses. — [FAQ – Modeled conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_modeledconversionsfaq) [Official]
- Modeled conversions for UET Consent Mode launched around August 2025 for eligible EEA/CH/GB advertisers. — [PPC News Feed, 2025-08 (search-result text)](https://ppcnewsfeed.com/ppc-news/2025-08/microsoft-launches-modeled-conversions-for-uet-consent-mode/) [Third-party]. Older CMP-vendor articles stating "Microsoft does not model conversions" (e.g. [Usercentrics](https://usercentrics.com/knowledge-hub/microsoft-uet-consent-mode/), search-result text) are **outdated**.
- Microsoft Clarity enforces consent signals for EEA/UK/CH visits from **31 October 2025**; Clarity Consent Mode is on by default for those users. — [Clarity Consent Mode (ms.date 2025-08-14)](https://learn.microsoft.com/en-us/clarity/setup-and-installation/consent-mode) [Official]
- Implementation errors are a real risk: an advertiser reported zero conversions and no UET activity after implementing consent mode (2026-01-09); the Microsoft moderator pointed to UET Tag Helper to validate the consent signal. — [Microsoft Q&A, 2026-01-09](https://learn.microsoft.com/en-us/answers/questions/5700812/microsoft-ad-tracking-consent-mode) [Official forum]
- Third-party CMP vendors disagree on the default when no `ad_storage` default is set (Cookiebot: granted; Didomi: denied in EEA). Microsoft's own page says granted. — search summary of [Cookiebot](https://support.cookiebot.com/hc/en-us/articles/12452886794908-Setting-up-Universal-Event-Tracking-for-Consent-Mode) and [Didomi](https://didomi.io/blog/microsoft-universal-event-tracking-uet-consent-mode) [Third-party, search-result text]

### Inferences
- In a Danish account, observed conversions undercount actual Microsoft-driven orders by roughly the share of visitors who decline marketing cookies (Danish consent rates are not documented here). A gap to the shop's orders is therefore expected and is not by itself a tracking fault.
- A mid-size Danish webshop account may well be **below 700 clicks per week**. Then no modeled conversions are added and the consent gap stays unfilled. The assistant should not assume modeling is active unless the UI notification or uplift report shows it.
- A sudden drop of conversions to zero right after a CMP/consent change points to a consent implementation fault (tag blocked, default never updated), not to ad performance.

### Gaps
- No Microsoft-published figure for the share of conversions typically lost to consent denial, or for modeling recovery rates.
- Whether Microsoft also enforces on Clarity-linked UET tags separately beyond the Oct 2025 Clarity rule: not stated.

## 3. Attribution: model, click date vs. conversion date, cross-device, and why numbers differ from Google Ads, GA4 and the shop

### Takeaway
Default attribution is **last click** per conversion goal (earlier clicks become "Assists"). **Data-driven attribution (DDA)** exists as a per-goal option since April 2026 (rolled out to all advertisers by end of May 2026, for Max conversions/Max conversion value/Enhanced CPC). Conversions are **reported on the date of the ad click**, cross-device conversions are included automatically (since June 2023), and Microsoft only counts conversions preceded by its own click/impression. So Microsoft, Google Ads, GA4 and the shop will never match 1:1.

### Cited Findings
- "Microsoft Advertising uses the last ad click attribution… the last (most recent) click before the conversion gets credit"; earlier ad clicks count as assists. (Help page dated 2026-06-18 still describes only last click.) — [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks) [Official]
- `Assists` = conversions from other ads in the same account preceded by clicks on this ad; the assist click must be within the goal's conversion window. — [CampaignPerformanceReportColumn](https://learn.microsoft.com/en-us/advertising/reporting-service/campaignperformancereportcolumn?view=bingads-13) [Official]
- API `AttributionModelType` per conversion goal: `LastClick` (**default**; view-through excluded from Conversions, reported in View-through and All conversions), `LastTouch` (view-through included in Conversions; Audience campaigns only), `DataDriven` ("attributed across all ad interactions that lead to a conversion"). — [AttributionModelType](https://learn.microsoft.com/en-us/advertising/campaign-management-service/attributionmodeltype?view=bingads-13) [Official]
- DDA announced 2026-04-21 ("assigns credit across the full customer journey"); beta customer nearly doubled conversion volume at stable CPA (Microsoft's own case claim). — [Microsoft blog, 2026-04-21](https://about.ads.microsoft.com/en/blog/post/april-2026/an-ads-ecosystem-built-for-the-ai-era) [Official]
- "Data-driven attribution is now rolling out to all advertisers by the end of May" 2026; works for Maximize Conversions (opt. tCPA), Maximize Conversion Value (opt. tROAS) and Enhanced CPC. — [Microsoft blog, 2026-05-19](https://about.ads.microsoft.com/en/blog/post/may-2026/new-import-center-and-other-product-news-for-may-2026) [Official]
- Trade press warns that conversion credit redistributes between campaigns after switching to DDA (branded search and retargeting typically lose credit) and that DDA needs enough conversion volume. — [Search Engine Land (search-result text)](https://searchengineland.com/microsoft-rolls-out-ai-powered-bidding-reporting-and-import-updates-for-advertisers-478223); [affectgroup (search-result text)](https://affectgroup.com/blog/microsoft-ads-data-driven-attribution-explained/) [Third-party]
- Last-touch attribution for automated bidding on the Audience Network (counts view-through for bidding) was announced Feb 2023. — [Microsoft blog Feb 2023](https://about.ads.microsoft.com/en/blog/post/february-2023/market-expansion-and-other-product-updates-for-february); [MediaPost (search-result text)](https://www.mediapost.com/publications/article/381753/microsoft-makes-last-touch-attribution-for-automat.html)
- **Click date:** "Conversions are reported based on the click date rather than the conversion date, which means there may be a delay before all conversions are fully reflected… This can temporarily inflate your CPA or deflate your ROAS." — [Understanding conversion delay](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_conversiondelay) [Official]; also "Microsoft Advertising reports conversions on the date of the ad click, whereas some other reporting tools attribute them to the date of the conversion" — [Discrepancy article](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_baawdiscrepancy) [Official]
- Cross-device attribution model announced 2023-06-07, "later this month"; e.g. click on laptop, convert on phone → credited to the laptop click; no settings; "small increase" in conversions. — [Microsoft blog, 2023-06-07](https://about.ads.microsoft.com/en/blog/post/june-2023/new-web-insights-and-other-product-updates-for-june); described as current in [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks) [Official]
- Microsoft's documented reasons for gaps vs. Google Ads/GA4/own logs: different goal definitions, windows and counting (Unique vs. All); duplicate tags/goals; test/fraud orders not filtered; **Microsoft includes cross-device conversions** (Google Ads shows them in estimated columns; GA usually doesn't); **GA does cross-channel attribution**, so conversions Microsoft claims may go to other channels in GA; users converting directly or via other channels are never counted by Microsoft; **Google's move to data-driven attribution in GA4** "may be causing large differences"; time zone for reporting must be the same. — [Discrepancy article](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_baawdiscrepancy) [Official]
- Microsoft moderator (2026-02-17): Microsoft Advertising conversion tracking "should be considered the source of truth for evaluating Microsoft Ads performance"; GA4 "may undercount conversions due to cookie restrictions, session stitching differences, or attribution rules that credit other channels". — [Microsoft Q&A, 2026-02-17](https://learn.microsoft.com/en-us/answers/questions/5778112/ga4-and-microsoft-advertising-conversion-data-disc) [Official forum; note: Microsoft has an interest in this answer]
- Shop vs. ad platforms: the shop counts all completed orders, platforms only ones tied to a click; customers closing the browser before the thank-you page loads (one report ~20 % loss), consent banners, duplicate tags, later refunds/cancellations all widen the gap. — [Shopify community threads and vendor blogs (search-result text)](https://community.shopify.com/t/reported-conversions-do-not-match-number-of-orders/326215) [Third-party, anecdotal]

### Inferences
- Because conversions are booked to the click date, a period's Microsoft conversions **keep rising for up to the conversion window (30 days default)** after the period ends. The shop's orders for the same dates are final immediately. Comparing "last 7 days" Microsoft revenue with "last 7 days" shop revenue therefore always undercounts Microsoft.
- Microsoft conversions can **exceed** GA4 conversions for Microsoft traffic (cross-device, last click within Microsoft only, GA4 cross-channel/DDA). They can also be **below** the shop's orders (consent, direct/other channels). Neither direction alone proves a tracking fault.
- After a goal is switched to DDA, campaign-level conversions shift without any real performance change. Before/after comparisons across the switch date are not like-for-like. The switch date should be checked in change history.
- Bing organic vs. Bing CPC must be separated in GA4 when comparing (per Microsoft Q&A answers, search-result text).

### Gaps
- No Microsoft help article (as of the 2026-06-18 help snapshot) describing DDA methodology, minimum volume, or whether DDA restates history. Whether the default model for *new* goals changed to DDA after May 2026 is unconfirmed (the API reference still says LastClick is the default).
- No published study quantifying typical Microsoft Ads vs. GA4 vs. shop gaps for EU/Danish webshops.

## 4. Reporting: latency, incomplete days, time zones, report types and columns, aggregation pitfalls, match types, search-term thresholds

### Takeaway
Clicks and impressions can lag up to 1 hour, UET conversions 2–3 hours, offline/app conversions 5 hours, search terms 3 hours, share-of-voice/impression-share data up to 16 hours, auction insights 2.5 days, PMax search-term insights 3 days. Quality score updates once a day, 14–18 hours after the UTC day ends. "Books close" about 3 hours after the click, but **conversion totals for recent click dates keep growing over the conversion delay** (Microsoft measures the days to 90 % of conversions). The API's relative date ranges default to **Pacific time** unless `ReportTimeZone` is set. Data retention is 36 months.

### Cited Findings
**Latency and freshness** [Official]
- Freshness table: Clicks and Impressions "1 hour might not appear"; **UET conversions 2 hours**; **non-UET (app install, offline) 5 hours**; Search terms (Keywords tab, Dimensions, Search terms report) 3 hours; **Search terms insight report 3 days**; Top mover 3 days; **Auction insights 2.5 days**; Negative keyword report 3 hours; **Share of voice report 16 hours**; Change history ~1 hour. Performance data retained **up to 36 months**. — [Is my data updated in real time?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_datafreshness)
- API: "it can take up to two hours for the system to process the click (3 hours for conversions)… Data is generally considered complete with books closed after 3 hours"; invalid-traffic adjustments "might take a week or more". `ReturnOnlyCompleteData=true` returns error 2004 `NoCompleteDataAvaliable` until processed; the report header shows "Last Completed Available Day/Hour" (always UTC) and "Potential Incomplete Data: true/false". — [Reports guide (ms.date 2025-06-26)](https://learn.microsoft.com/en-us/advertising/guides/reports?view=bingads-13)
- Conversion delay column (campaign, goal, portfolio grids; Campaign, Goal and Account performance reports): "how many days it typically takes to collect 90% of conversions" for the selected range, with a hover showing "the recommended date to evaluate performance inclusive of delayed conversions"; data only for clicks from **1 June 2025**; announced 2025-11-18; updated daily; online and offline conversions. — [Understanding conversion delay](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_conversiondelay); [Microsoft blog, 2025-11-18](https://about.ads.microsoft.com/en/blog/post/november-2025/asset-level-editorial-review-and-other-updates-for-november); [Search Engine Roundtable, 2025-11-19](https://www.seroundtable.com/microsoft-advertising-new-features-40451.html)

**Aggregation pitfalls** [Official]
- `DayOfWeek` values 1–7 with **1 = Sunday**; DayOfWeek/HourOfDay aggregate across all weeks/days in the range. - `QualityScore` over a multi-day range shows the *latest* score on every day; `HistoricalQualityScore` shows the score calculated on each date. Quality impact column: 3 = >500 extra impressions/day possible, 2 = 100–500, 1 = <100. — [Quality score in depth](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_aboutqualityscore)

- Only the search-ads **clicks** metric is MRC-accredited. — [Reports guide](https://learn.microsoft.com/en-us/advertising/guides/reports?view=bingads-13)

### Inferences
- The search-term report under-represents spend and impressions. Summing search-term spend will not reconcile with campaign spend. Wasted-spend findings from search terms are therefore a lower bound.
- "Last 3 days incomplete" is right for clicks/cost, but for conversions and ROAS the incomplete window equals the conversion delay (often several days or weeks for considered purchases). It should be read from the Conversion delay column, not assumed.
- Copenhagen vs. Pacific: normally 9 hours apart, but 8 hours during the weeks when US and EU daylight-saving changes don't coincide (mid-March to late March, late October to early November). This is general time-zone knowledge, not from Microsoft. A report without `ReportTimeZone` can thus shift "yesterday" by a day for early-morning Danish requests.
- Impression share at keyword level can be blank for low-volume keywords. Blank does not mean 0 %.

### Gaps
- No official per-report latency for the Conversion (goal) performance report beyond "UET conversions 2 hours".
- Whether impression-share columns via the API have a distinct documented latency: the help center says SOV report "16 hours". I found no API statement of "14–18 hours" for IS.
- The "Other search terms" row could only be confirmed from search-result text (the apex help URL isn't fetchable).

## 5. Statistical reading: sample sizes, experiments and significance, seasonality, day-of-week, waiting after changes

### Takeaway
Microsoft's own numbers: give automated bidding **≥30 conversions in the previous 30 days**, don't judge during the **1–2 week learning period**, then run **2–4 more weeks** before evaluating, and adjust tCPA in steps of **10–15 %**. Experiments: 50/50 split, two weeks identical plus at least two weeks A/B (**≥4 weeks**), significance shown per metric (green/red/grey). The confidence level is not documented. Practitioner minimums for ad/keyword decisions range from about 30 clicks (tentative) to 100–300 clicks or 7–20 conversions per variant, always with at least one full week.

### Cited Findings
**Microsoft (official)**
- Bids start changing within 2 hours of enabling a bid strategy; it "needs to run for up to two weeks" to bid optimally; changing strategy, budget, conversion settings or adding/removing ad groups/keywords during that time can lengthen it. Playbook steps: set-up 30 days ("at least 30 conversions in the previous 30 days"; base tCPA on actual CPA of the previous 30 days), learning 1–2 weeks ("not evaluating… based on these two weeks"), run 2–4 weeks after learning, then evaluate; "keep your conversion goal window in mind"; tCPA adjustments within 10–15 %. Each of Max conversions, tCPA and tROAS: "accumulate at least 30 conversions before evaluating its performance". — [Bid strategies](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy)
- Since **4 August 2025**, standalone Target CPA/Target ROAS can't be set up for new campaigns (use Max conversions/Max conversion value with a target); API/bulk updates to those strategies are auto-converted; existing ones and portfolios unaffected. — [Bid strategies – Changes to bid strategies options](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy)
- Bid strategy statuses include "Limited: low data volume" (not enough conversions or revenue), "Limited by target", "Limited by budget", "Limited by inventory", "Limited by max CPC". — [Bid strategy report](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategyreport)
- "Limited by auto-bidding target" doesn't mean anything is wrong; status updates the next day after a target change; Microsoft does "not recommend frequent target changes". — [Bid strategies](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy)
- Experiments: Search campaigns only (not with DSA enabled); split can't be changed while running; recommended **50/50**; search-based split (faster significance; suits bidding tests) vs. cookie-based (more accurate for ad copy/imagery); comparison table colours green/red/grey, grey = "no statistically significant performance difference", significance shown under each metric; don't change the base campaign during the test; budget only via the base campaign; max 10 experiments per campaign, 1 running at a time. — [Discover the possibilities with experiments](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_experiments_about)
- "For the first two weeks of the experiment, keep the original and experiment campaigns identical… then let the experiment run in A/B mode for at least two weeks (so at least four weeks in total)." — [Examples and tips for experiments](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_experiments_bestpractices)
- Seasonality adjustments: ≤14 days, set the expected conversion-rate change in %, only for target CPA/ROAS bid strategies; device scoping; available for portfolios and shared budgets (fully available by May 2026). — [Seasonality adjustments](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_seasonalityadjustments); [Microsoft blog, 2026-05-19](https://about.ads.microsoft.com/en/blog/post/may-2026/new-import-center-and-other-product-news-for-may-2026)
- Data exclusions: max 14 days, **recommended ≤7 days**; only for strategies active ≥30 days with stable performance, not in the initial 30-day learning period; add extra days for conversion delay; don't affect reporting; campaign level only. — [Data exclusions for auto-bidding](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_dataexclusions)
- Microsoft recommends judging PMax placements over several weeks or full conversion cycles. — [ppc.land on PMax placement report, May 2026 (search-result text)](https://ppc.land/performance-max-placement-reports-now-show-conversions-clicks-and-spend/)
- AI Max/conversion-based bidding working threshold of 30 conversions in 30 days (ppc.land, Aug 2026, search-result text). — [ppc.land](https://ppc.land/microsoft-says-ai-max-testers-gained-8-more-conversions/)

**Practitioners (third-party)**
- Adalysis (Brad Geddes, 2015-11-10) minimum data before reading an ad test, by traffic level: low traffic 350 impressions / 300 clicks / 7 conversions; mid 750 / 500 / 13; high 1,000 / 1,000 / 20; well-known brand terms 100,000 / 10,000 / 100–1,000. These appear to be separate minimums per metric type (impressions for CTR, clicks for conv. rate, conversions for CPA). "Always use a minimum of a week of data", a month or three is fine. Example: 97 impressions gave "97 % confidence" for a winner that reversed at 3,163 impressions. — [Adalysis](https://adalysis.com/blog/how-much-data-should-you-have-before-examining-an-ad-test-result/)
- SEJ (2020-06-29): compare month-over-month and year-over-year before concluding (a −20 % MoM drop was +128 % YoY, i.e. seasonal); don't aggregate conversion types of different value; small campaigns with a few dozen clicks give no reliable expected value; beware "statistical significance" misuse. — [Search Engine Journal](https://www.searchenginejournal.com/interpret-ppc-data-correctly/371937/)
- Other practitioner thresholds (search-result text): about 30+ clicks or 3+ orders before keyword inference, 15 clicks with zero orders before negating a term (Amalyze); 100 clicks per ad/keyword before comparing (SEJ/Geddes); at 1 % conversion rate ≥100, better 300 clicks before calling zero conversions (WebmasterWorld 2008); Search Engine Land warns that "10 clicks in 7 days and no conversions → bid down" rules kill long-tail terms; use expected clicks per conversion instead. — [Amalyze](https://amalyze.com/resources/glossary/statistical-significance); [SEJ](https://www.searchenginejournal.com/how-many-ppc-ads-should-you-test/12252/); [Search Engine Land](https://searchengineland.com/?p=111888) [Third-party]
- No Microsoft-specific or Danish benchmark for day-of-week effects was found. Microsoft confirms ad scheduling uses the searcher's local time and the DayOfWeek aggregation merges all weeks. — [Changing your account time zone](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_changetimezone); [Reports guide](https://learn.microsoft.com/en-us/advertising/guides/reports?view=bingads-13)

### Inferences
- A useful zero-conversion test is expected conversions = clicks × the ad group's conversion rate. With an ad group conversion rate of 2 %, 30 clicks give 0.6 expected conversions; zero is then unsurprising (P(0) ≈ e^-0.6 ≈ 55 %). At 150 clicks (3 expected) P(0) ≈ 5 %. This is standard Poisson reasoning, not a Microsoft source.
- With a 30-day default conversion window and click-date reporting, a change should be judged on click dates that are at least "conversion delay" days old, in addition to the 7–14 days of post-change time.
- Experiments: because Microsoft doesn't publish its confidence level, the assistant should report the in-UI significance colour and the raw numbers, not claim "95 %".

### Gaps
- Microsoft's experiment significance method and threshold (95 %?) are undocumented; only Google documents 95 % for its own experiments ([Google Ads help](https://support.google.com/google-ads/answer/9232676)), which must not be assumed for Microsoft.
- No source for the claim "Microsoft stops optimising below 15 conversions in 30 days" (see Against the current rules).

## 7. Against the current rules (src/ai/prompt.ts and src/ai/playbooks/microsoftAds.ts)

### Takeaway
Most measurement rules hold up. Five need correcting: (1) the 14–18 h latency belongs to **quality score**, not impression share; (2) "newest 1–3 days incomplete" is too short for conversions and ROAS, because Microsoft books conversions to the click date and offers a Conversion delay column; (3) "15 conversions in 30 days" has no source; Microsoft says ≥30 in 30 days; (4) data exclusions are max 14 days (≤7 recommended), and seasonality adjustments only work with target CPA/ROAS; (5) offline time is not UTC-only. Missing are rules on click-date reporting, Include in Conversions vs. All conversions, modeled conversions, DDA and the Google conversion-goal import.

### Cited Findings
**prompt.ts – "Documented Microsoft Advertising rules" → Reports line**
- "impression share data arrives 14–18 hours after the UTC day ends" — **contradicted/misattributed.** The API attaches "typically updated 14–18 hours after the UTC day ends" to `QualityScore`, `ExpectedCtr`, `AdRelevance`, `LandingPageExperience`, not to impression-share columns. — [KeywordPerformanceReportColumn](https://learn.microsoft.com/en-us/advertising/reporting-service/keywordperformancereportcolumn?view=bingads-13); [CampaignPerformanceReportColumn](https://learn.microsoft.com/en-us/advertising/reporting-service/campaignperformancereportcolumn?view=bingads-13). The help center gives the Share of voice report "16 hours may not appear". — [Data freshness](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_datafreshness). Suggested wording: "quality score updates once a day, 14–18 h after the UTC day ends; impression share (share of voice) can lag up to ~16 h; auction insights 2.5 days".
- "can't be combined with hourly data" / error 2053 — **not verified** in the pages read. The reports guide documents IS columns as mutually exclusive with certain *attribute* columns (BidMatchType, AdId, AdDistribution…). — [Reports guide](https://learn.microsoft.com/en-us/advertising/guides/reports?view=bingads-13). Keep it if it comes from the app's own error handling, but treat it as unverified.
- "quality score updates once a day" — **confirmed**. — [Quality score in depth](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_aboutqualityscore)
- "the newest 1–3 days are incomplete (conversions are late)" — **partly confirmed, needs refinement.** Books close after about 3 hours for clicks and conversions processing ([Reports guide](https://learn.microsoft.com/en-us/advertising/guides/reports?view=bingads-13)), but conversions are reported on the **click date**, so recent click dates keep gaining conversions until the conversion delay has passed (Microsoft's Conversion delay column = days to 90 % of conversions; clicks from 2025-06-01). — [Understanding conversion delay](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_conversiondelay). Suggested: "cost and clicks: the newest ~3 hours/today incomplete; conversions/ROAS: exclude click dates newer than the campaign's Conversion delay (fallback 3–7 days); invalid-click credits can change data a week or more later".
- "Day of week 1 = Sunday" — **confirmed**. — [Reports guide](https://learn.microsoft.com/en-us/advertising/guides/reports?view=bingads-13)

**prompt.ts – "Microsoft Advertising know-how"**
- "Microsoft stops optimising below 15 conversions in 30 days; the playbook wants at least 30" — **15 not found** in any Microsoft page read. Microsoft recommends "at least 30 conversions in the previous 30 days" and to "accumulate at least 30 conversions before evaluating"; low volume shows as "Limited: low data volume". — [Bid strategies](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy); [Bid strategy report](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategyreport). Suggest dropping "15" or marking it as unsourced.
- "Since August 2025 campaigns can't be moved to standalone Target CPA/Target ROAS" — **confirmed** (4 August 2025). — [Bid strategies](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy)

**prompt.ts – "How you reason" (rules 3, 4, 5, 7)**
- Rule 3 "the newest 1–3 days are incomplete": same refinement as above (use Conversion delay for conversion metrics).
- Rule 4 data limits (loser after 1.5–2× target CPA or 30 clicks; ~100 clicks or 10 conversions per side; judge a change after 7 full days and 30 clicks, 14 days when learning) — **consistent with practitioner ranges but not Microsoft-documented**; Microsoft's own numbers are stricter for bid strategies: learning 1–2 weeks, then **2–4 more weeks** before evaluating, ≥30 conversions. — [Bid strategies](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy). Practitioner ad-test minimums are higher than "100 clicks or 10 conversions" for low-traffic accounts (Adalysis: 300 clicks / 7 conversions low traffic, 500/13 mid, 1,000/20 high; ≥1 week). — [Adalysis](https://adalysis.com/blog/how-much-data-should-you-have-before-examining-an-ad-test-result/). The expected-sales idea in rule 4 is sound (see section 5 inference).
- Rule 5 "Microsoft's conversions are not the shop's orders and not Google's" — **confirmed**, with documented causes: click-date booking, last click within Microsoft, cross-device inclusion, GA4 cross-channel/DDA, consent losses, no fraud/duplicate filtering. — [Discrepancy article](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_baawdiscrepancy)
- Rule 7 "bids and targets in steps of 10–20 %" — Microsoft says tCPA adjustments "within 10–15 %", which is **narrower**. — [Bid strategies](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_bidstrategy). The playbook's guardrail "Mål-CPA/-ROAS: ±10–15 %" matches Microsoft.

**prompt.ts – "Standard diagnoses"**
- "conversions drop to zero while clicks hold = tracking or checkout" — **confirmed** by Microsoft's diagnostics trigger "No conversions in seven days—your tracking may need to be fixed", and by consent-implementation failures. — [Diagnostics tile](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_campaign_diagnostictiles); [Microsoft Q&A](https://learn.microsoft.com/en-us/answers/questions/5700812/microsoft-ad-tracking-consent-mode). **Missing**: check for a consent/CMP change and for a goal edit (Include in Conversions toggled, DDA switch, new imported goal) in change history.

**Missing rules (suggested additions)**
- Conversions are reported on the **click date**; recent ROAS/CPA is understated until the Conversion delay has passed. Use the Conversion delay column/hover date. — [Understanding conversion delay](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_conversiondelay)
- `Conversions`/`Revenue`/CPA/ROAS include only goals with Include in Conversions on (or campaign-level goals). `All conversions` includes everything, plus view-through by default. Always say which column a number comes from. — [Conversions versus All conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_convsvsallconvs); [ConversionGoal](https://learn.microsoft.com/en-us/advertising/campaign-management-service/conversiongoal?view=bingads-13)
- Goal setting changes (window, counting, campaign-level goals) apply only going forward. A before/after comparison across such a change isn't like-for-like. — [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks); [Campaign level conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_campaignlevelconv)
- Attribution model per goal: LastClick (default), DataDriven (since Apr/May 2026), LastTouch (Audience). A switch to DDA redistributes credit between campaigns. — [AttributionModelType](https://learn.microsoft.com/en-us/advertising/campaign-management-service/attributionmodeltype?view=bingads-13); [Microsoft blog, 2026-05-19](https://about.ads.microsoft.com/en/blog/post/may-2026/new-import-center-and-other-product-news-for-may-2026)
- Modeled conversions (EEA): fractional, inside `Conversions`; require ≥700 weekly clicks in the market. Fractional conversion counts are normal, not an error. — [FAQ – Modeled conversions](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uet_modeledconversionsfaq)
- Microsoft does not filter test/fraud/duplicate conversions. A spike in conversions without matching shop orders → check duplicate tags/goals first. — [How does conversion tracking work?](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_uetv2howctworks)
- Search term report shows only terms with "a significant number of clicks". Its totals won't match campaign totals, and wasted spend found there is a lower bound. — [Run a search term report](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_aboutsearchqueryreport)

- After an account time-zone change, wait a couple of days before optimising, and don't compare hourly data across the change date. — [Changing your account time zone](https://learn.microsoft.com/en-us/advertising/msa-help/hlp_ba_conc_changetimezone)
